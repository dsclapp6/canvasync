One row per thing the user asked for. Three columns, three separate claims:

- **Built** — the code exists, it parses, its unit tests pass.
- **Stressed** — it was run against real or copied real data and deliberately attacked:
  bad input, empty input, boundary dates, the case the happy path hides.
- **Complete** — re-checked end to end *after* the last change to it, in the app.

A box is ticked only when that specific claim has been checked. `~` means partly, with the
gap named. An empty box is an empty box; nothing here is ticked in advance of the work.
